================================================================================
GYMFITNESS DATABASE SCHEMA
================================================================================
Nguồn  : database/01_tables.sql + database/02_triggers.sql
Ánh xạ  : backend/app/models/*.py (SQLAlchemy 2.0)
DBMS    : MySQL 8.0+
Ký tự   : utf8mb4 / collation utf8mb4_0900_ai_ci

TỔNG QUAN
--------------------------------------------------------------------------------
- Số bảng        : 44
- Số trigger     : 10
- Số foreign key : 83

QUY ƯỚC CHUNG
--------------------------------------------------------------------------------
- Khóa chính dùng CHAR(36), ứng dụng sinh UUID trước khi INSERT.
- Thời gian lưu UTC, kiểu DATETIME(6).
- created_at/updated_at mặc định CURRENT_TIMESTAMP(6), updated_at có ON UPDATE.
- Tiền dùng NUMERIC(14,2) (Decimal), không dùng float. Tiền tệ mặc định VND.
- Soft-delete qua cột deleted_at (DATETIME(6) nullable).
- Optimistic locking qua row_version (INTEGER NOT NULL DEFAULT 1).
- Cột trạng thái dùng VARCHAR + CHECK (không dùng native ENUM).

KÝ HIỆU
--------------------------------------------------------------------------------
PK     = khóa chính (primary key)
UQ     = unique
FK     = khóa ngoại (foreign key), ghi rõ hành vi ON DELETE
NN     = NOT NULL
DEF    = giá trị mặc định (server_default)

9. TRIGGERS (database/02_triggers.sql)
================================================================================

1.  trg_user_addresses_one_default_insert
    BEFORE INSERT trên user_addresses — chặn thêm địa chỉ mặc định thứ 2.

2.  trg_user_addresses_one_default_update
    BEFORE UPDATE trên user_addresses — chặn đặt 2 địa chỉ mặc định.

3.  trg_check_ins_one_open_insert
    BEFORE INSERT trên check_ins — chặn check-in mở trùng (chưa checkout).

4.  trg_check_ins_one_open_update
    BEFORE UPDATE trên check_ins — chặn chuyển 2 check-in cùng mở.

5.  trg_trainer_availability_no_overlap_insert
    BEFORE INSERT trên trainer_availability — chặn khung giờ rảnh chồng lấn.

6.  trg_trainer_availability_no_overlap_update
    BEFORE UPDATE trên trainer_availability — chặn khung giờ rảnh chồng lấn.

7.  trg_pt_bookings_validate_insert
    BEFORE INSERT trên pt_bookings — booking REQUESTED/ACCEPTED phải nằm trong
    availability AVAILABLE; chặn trùng lịch của trainer và của member.

8.  trg_pt_bookings_validate_update
    BEFORE UPDATE trên pt_bookings — tương tự validate cho UPDATE.

9.  trg_class_sessions_no_overlap_insert
    BEFORE INSERT trên class_sessions — chặn trainer hoặc room bị trùng giờ
    với lớp SCHEDULED khác.

10. trg_class_sessions_no_overlap_update
    BEFORE UPDATE trên class_sessions — tương tự chặn trùng cho UPDATE.

Lưu ý: trigger chỉ là lớp bảo vệ cuối. Service layer vẫn phải dùng transaction
và SELECT ... FOR UPDATE để xử lý request đồng thời.

10. QUY TẮC XÓA (ON DELETE)
================================================================================

- CASCADE      : xóa theo (user_profiles, user_addresses, refresh_tokens,
                 password_reset_tokens, trainer_specialties, product_images,
                 cart_items, carts, notifications).
- SET NULL     : gỡ liên kết khi xóa (member.user_id, các cột *_by, file owner,
                 source address, ...).
- RESTRICT     : cấm xóa nếu còn dữ liệu lịch sử/nghiệp vụ (subscription, payment,
                 check-in, ledger, booking, ...).
